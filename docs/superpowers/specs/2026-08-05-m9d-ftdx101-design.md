## Context

M9c closed 30/07/2026 with the FTdx10 registered and every
neutral-core seam a second model needs already built (dialect
constructor, MT combined form, extable profiles, dialecttest,
capability-driven wiring, E1–E6). The FTdx101D/MP is the roadmap's
next radio. The CAT manual (rev 2308-L, 26 pages, acquired and
verified 05/08/2026 — provenance at
`docs/fixtures-private/manuals/m9d-manual-provenance.md`, gitignored)
covers BOTH models in one document; orchestrator reading found the
only per-model differences to be the ID answer (0681 FTDX101D /
0682 FTDX101MP), TX max-power EX value ranges we never interpret,
and the PC command's power range (off this project's surface).
Everything below that reading claims about the protocol is a
HYPOTHESIS the blind transcription chain must independently
re-establish; nothing in this spec is evidence.

## Stuart's decisions (05/08/2026, brainstorming)

1. **Two thin registrations.** `--model FTdx101D` and
   `--model FTdx101MP` both selectable; one dialect/driver/fake
   parameterised by CAT ID; probe refuses the wrong sibling's ID by
   name; Stage R/W evidence tracked per model.
2. **Two milestones.** M9d-1 (dialect + blind EX transcription,
   mirroring M9c-4) then M9d-2 (driver + fake + registration,
   mirroring M9c-6), each with the full spec/plan/milestone review
   cadence.
3. **The CHIRP blank-Skip deferral folds into M9d-2** (caps-aware
   skip construction mirroring the tag_display fold).
4. **Sibling packages, no family refactor.** The FTdx10 packages are
   not reopened; a future combined-form family abstraction is noted
   here as a possibility to revisit when the FTX-1 arrives (the radio
   that breaks the pattern), and deliberately not taken at n=2.
5. **(Rev 2, from the spec-review adjudication A1.) The designed
   FT-710/FTdx10 CHIRP delta is SANCTIONED.** The caps-keyed skip
   fold necessarily reclassifies the FT-710 too (`FieldScanSkip` is
   the zero FieldSupport on every registered radio), so the original
   FT-710 CHIRP byte-identity pin is replaced by a designed,
   baselined, removal-proven delta — which also fixes the ledgered
   FT-710 CHIRP→send block.

  external package (~1,464 frames each).
- Ten golden vectors hand-derived blind from the position charts,
  byte-compared through the codec, hash-frozen self-enforcingly;
  plus at least one D-vs-MP pair proving the two instances build
  IDENTICAL frames for identical inputs (this pair proves shared
  config, nothing more — the sharing HYPOTHESIS is carried by the
  applicability sweep below).
- **(Rev 2, A2.) The frame-geometry witness.** A separate quarantined

## M9d-1 evidence design (the blind chain, unchanged from M9c-4)

Three quarantined agents that never open the repository:

1. PDF-primary group-boundary ledger (row counts per P1/P2 group);
2. layout-led transcription A, count-preflighted against the ledger;
3. PDF-primary semantic transcription B.

Cross-checked with ZERO mismatches required on every leg before
anything enters the repo. **(Rev 2, A3.) The boundary-ledger leg
additionally performs a per-row, per-stored-property model-conditionality
sweep**: for every Table 2 row it records whether ANY marking
conditions membership, P1/P2 labels, function name, Digits, or
textness on FTDX101D vs FTDX101MP, and closes with an explicit
attestation (expected: zero such rows — the only conditional lines in
the document are P4 value ranges at the three MAX POWER items and the
PC command; a contrary finding STOPs the milestone, because the
shared-inventory design has nowhere to represent it).

Transcription briefs must name: the Table 2 merged-cell layout
hazard; the headers-above-token-rows grid convention (the FTdx10's
41-50 miscount trap — but NOT the expected byte counts, per the
geometry witness above); `pdftotext` only ever with `-layout`; and
the manual's printed quirks — record, don't resolve: the MP AM max
power "5 ~ 500" against P4 `005 ~ 050`; the EX grammar header
"P1: 01 - 05" against a Table 2 populating P1 01-04 only (the
FTdx10's already-pinned anomaly class); the OI mode legend's
"E: PSK E: DATA-FM-N" misprint; VM's detail title duplicating AM's
function name.
Transcription B is later COPIED (not imported) into
`internal/fakedx101`; the two-source property is enforced by the
existing mechanism (staleness test + transport cross-check +
recursive import fence), which M9c-6 red-proved.

## M9d-2 — driver, fake, registration (branch `m9d2-ftdx101-registration`)

- **(Rev 2, A4.) The capability matrix comes FIRST.** Before the
  M9d-2 plan is written, a per-model evidence/assumption matrix over
  EVERY `spec.Capabilities` field (and the framing/control-line/
  discovery behaviours no field expresses): each entry either
  MANUAL-EVIDENCED with its layout citation, or ASSUMED with its
  register entry and named Stage R lift. Capabilities are never
  evidence for themselves; tests derived from them pin choices, not
  facts. (This replaces rev 1's circular "confirmed from capabilities
  at plan time" for the bank core fields — they are confirmed from
  the matrix.)
- `core/driver/ftdx101`: ONE driver parameterised by model
  name + CAT ID, producing registered models `FTdx101D` and
  `FTdx101MP`. Every `spec.Capabilities` field EXPLICIT (the
  zero-value class); `writeTrialsComplete=false` pinned PER MODEL,
  consulted by no production code; MT-only atomic reads; full-range
  501..599+EMG discovery with the FTdx10's ~2.5s/Open budget shape;
  MT-only writes (choreography decided from this manual, expected to
  match the FTdx10's); `TagDisplay` reported `Unavailable` (P11
  fixed — the frame carries no display flag); 197-item-class settings
  read sized by the real inventory count.
- Probe refuses the wrong sibling's ID with BOTH names spelled out
  ("radio identifies as FTdx101MP; you selected FTdx101D"), tested in
  both directions. **(Rev 2, A5.) The mechanism is named:**
  `driver.WrongRadioError` carries IDs only and `cmd/rigprog/probe.go`
  has no ID→name mapping, so the refusal needs a defined extension —
  preferred shape: an additive, optional found-model resolution
  (registry-fed ID→name lookup at the RENDER sites, or an additive
  field on the error), chosen so the shared type's `Error()` text for
  the FT-710/FTdx10 is PINNED UNCHANGED. The both-direction tests
  must also hold the existing contracts: `errors.Is(ErrWrongRadio)`,
  `errors.As(*WrongRadioError)` with Want/Got IDs preserved, refusal
  BEFORE any discovery traffic, and port closure. A D capture does
  not lift an MP assumption: the driver-level ASSUMED register
  (~nine entries, M9c-6's shape) is tracked per model.
- `internal/fakedx101`: one fake, ID-parameterised; EX inventory
  GENERATED from its own copy of transcription B with staleness +
  cross-check + import fence; register of assumed behaviours;
  fakeradio's seven fault options omitted with the stated reason,
  as fakedx10 does.
- Registration: presence pins land FIRST (two-sided structural tests
  are blind to symmetric removal — M9c-6 red proof 4); wiring rows;
  radiotext prose per model (EraseProcedure / FirmwareGuidance /
  ProbeFirmwareNote non-empty; ToneScanSkipVerification may stay
  empty while writeTrialsComplete=false); simulated-tokens guard
  rows; the sentinel sweep treated as a GREP-VERIFIED enumeration,
  not a planned list (M9c-6 found 11 sites against the plan's 5).
- **CHIRP blank-Skip fix (the folded deferral — REWRITTEN rev 2 per
  A1/A2 of the adjudication and Stuart's sanction, decision 5):**
  caps-aware skip construction. On a radio whose `FieldScanSkip` is
  Unsupported both directions — TODAY, EVERY registered radio — a
  blank Skip cell yields `{Unknown}` (NOT Unavailable: both drivers'
  read paths return Unknown, and Unavailable would mark every
  imported row Modified through diff's whole-struct compare) and an
  "S" cell yields `{Unknown}` plus a NON-BLOCKING LossEntry. A future
  radio with genuine support keeps today's blank→{Known,false} /
  "S"→{Known,true}. The FT-710 and FTdx10 CHIRP output changes are
  DESIGNED DELTAS: baselined, recorded verbatim, proven by removal.
  The plan MUST consult every consumer of ScanSkip state (Codex's
  enumeration): `codeplug` validation (`fieldstate.go`,
  `validate.go`), diff membership/state, both drivers' write gates,
  JSON persistence + digest, native CSV import/export, frontend
  rendering/editability (`columns.js`, `ChannelGrid.svelte`), and
  clone verification's deliberate ScanSkip exclusion — enumerating
  each one's behaviour change or proving it unaffected.
- **Byte identity:** FT-710 and FTdx10 zero diffs EXCEPT designed
  deltas recorded verbatim — the registry-driven model lists (top
  usage, `GetSupportedModels`, radiotext index, **and (rev 2, A6)
  `UnknownModelError.Supported` with its rendered error**) gain two
  rows, plus the sanctioned CHIRP skip delta above; the delta class
  M9c-6 established. Manifest reproduced from a clean worktree at the
  base commit; deltas proven by removal, never inferred from a hash.
  **(Rev 2, A6.) First fake-only baselines for EACH sibling** across
  the M9c-6 manifest's full leg class (probe / read / settings /
  diff / export / CHIRP / native round-trip — fourteen legs per
  model).

## Error handling

than guesses on malformed combined answers (window contingency stays
as M9c-3 ledgered it); writes disarmed per model; the `currentCaps`
unregistered-model FT-710 fallback stays as ledgered with the GUI
picker cluster — NOT touched here.
